# Анализ производительности Cursor CLI

## Проблема

Запросы через Cursor CLI в боте выполняются медленно (5+ минут), в то время как через Cursor IDE работают быстро.

## Возможные причины

### 1. Сканирование всей базы знаний

**Проблема:** Cursor CLI может сканировать все файлы в директории перед началом работы.

**Факты:**
- В базе знаний ~5704 файла
- Cursor CLI работает в директории со всей базой знаний
- Нет ограничений на контекст

**Решение:**
- Использовать `.cursorignore` для исключения ненужных файлов
- Ограничить контекст только нужными директориями

### 2. Системный промпт передается как часть запроса

**Проблема:** Системный промпт добавляется в начало запроса, увеличивая его размер.

**Текущая реализация:**
```python
full_query = f"""{self.system_prompt}

---

Запрос пользователя: {query}"""
```

**Возможные решения:**
- Использовать `.cursor/rules/` для системных промптов (Cursor CLI автоматически их загружает)
- Передавать промпт через переменную окружения (если поддерживается)
- Использовать более короткий промпт

### 3. Отсутствие кэширования

**Проблема:** Cursor IDE использует кэширование индексов файлов, а CLI каждый раз сканирует заново.

**Решение:**
- Использовать более быструю модель для простых запросов
- Ограничить количество файлов в контексте

### 4. Разница в работе IDE vs CLI

**IDE:**
- Использует инкрементальное индексирование
- Кэширует результаты
- Оптимизирован для интерактивной работы

**CLI:**
- Каждый раз сканирует файлы заново
- Нет кэширования
- Может быть медленнее для больших проектов

## Рекомендации по оптимизации

### 1. Создать `.cursorignore`

Исключить ненужные файлы из сканирования:

```
# Бинарные файлы
*.pdf
*.jpg
*.jpeg
*.png
*.gif
*.zip
*.tar.gz

# Системные файлы
.DS_Store
.obsidian/
node_modules/
.git/

# Большие директории (если не нужны для контекста)
Документы/Тачки/Соляра/
```

### 2. Использовать `.cursor/rules/` для системных промптов

Вместо передачи промпта в запросе, использовать файлы в `.cursor/rules/`:

```python
# Создать .cursor/rules/ в базе знаний
rules_dir = self.kb_path / ".cursor" / "rules"
rules_dir.mkdir(parents=True, exist_ok=True)

# Скопировать промпт туда
prompt_file = rules_dir / "system-prompt.md"
prompt_file.write_text(self.system_prompt)
```

### 3. Ограничить контекст

Использовать более короткие промпты и указывать конкретные файлы/директории в запросе.

### 4. Использовать более быструю модель для простых запросов

Для простых запросов использовать `gpt-4o-mini` вместо `gpt-4o`.

### 5. Добавить флаги оптимизации (если доступны)

Проверить доступные флаги:
- `--max-tokens` - ограничить размер ответа
- `--temperature` - контролировать креативность
- `--context-limit` - ограничить контекст (если есть)

## Реализованные оптимизации

### 1. Автоматическое создание `.cursorignore`

Бот автоматически создает `.cursorignore` при первом запуске, исключая:
- Бинарные файлы (PDF, изображения, архивы)
- Системные файлы (.DS_Store, .git/, .obsidian/)
- Временные файлы и кэши

### 2. Использование `.cursor/rules/` для системных промптов

Вместо передачи промпта в запросе, промпты копируются в `.cursor/rules/`:
- `bot-system-prompt.md` - промпт бота
- `kb-system-prompt.md` - промпт базы знаний

Cursor CLI автоматически загружает эти промпты, что оптимизирует производительность.

## Эксперименты для проверки

1. **Тест с `.cursorignore`:**
   - ✅ Реализовано автоматическое создание
   - Измерить время выполнения до/после

2. **Тест с `.cursor/rules/`:**
   - ✅ Реализовано автоматическое копирование промптов
   - Измерить время выполнения до/после

3. **Тест с ограниченным контекстом:**
   - Указать конкретные файлы в запросе
   - Измерить время выполнения

4. **Тест с разными моделями:**
   - Попробовать `gpt-4o-mini` для простых запросов
   - Сравнить время выполнения

## Метрики для отслеживания

- Время до первого ответа
- Общее время выполнения
- Количество просканированных файлов
- Размер контекста, отправляемого в API

## Дополнительные рекомендации

### Использование более быстрой модели

Для простых запросов можно использовать `gpt-4o-mini`:
```bash
CURSOR_MODEL=gpt-4o-mini
```

### Ограничение контекста в запросах

При запросах указывайте конкретные файлы или директории:
- ❌ "Найди информацию о..."
- ✅ "Найди в файле Документация/Авторасходы/Авторасходы.md информацию о..."

### Мониторинг производительности

Включите DEBUG логирование для отслеживания времени:
```bash
LOG_LEVEL=DEBUG
```
