# Автоматическая синхронизация с NextCloud

## Обзор

Бот автоматически синхронизирует локальную копию базы знаний с NextCloud:
- **При первом запуске**: скачивает базу знаний из NextCloud, если локальная папка пуста
- **После изменений**: автоматически загружает изменения в NextCloud
- **Периодически**: синхронизирует изменения из NextCloud (если включено)

## Как это работает

### 1. Инициализация при запуске

При запуске бота:
1. Проверяется, существует ли локальная папка `LOCAL_KB_PATH`
2. Если папка пуста, бот автоматически скачивает базу знаний из NextCloud
3. Если папка уже содержит файлы, инициализация пропускается

### 2. Синхронизация после изменений

Когда бот обрабатывает запрос через Cursor CLI и вносит изменения:
1. Бот отслеживает измененные файлы
2. Автоматически загружает изменения в NextCloud
3. Уведомляет пользователя о статусе синхронизации

### 3. Периодическая синхронизация

Если включена автоматическая синхронизация (`AUTO_SYNC=true`):
- Бот периодически (каждые `SYNC_INTERVAL` секунд) проверяет изменения в NextCloud
- Скачивает новые/измененные файлы из NextCloud
- Обновляет локальную копию

### 4. Двусторонняя синхронизация с удалением

Бот теперь поддерживает полноценную двустороннюю синхронизацию:

**При синхронизации в NextCloud (`sync_to_nextcloud`):**
- Загружает измененные локальные файлы в NextCloud
- **Удаляет файлы из NextCloud, которых нет локально** (если `delete_missing=True`)
- Обрабатывает ошибки 404 корректно (не пытается синхронизировать уже удаленные файлы)

**При синхронизации из NextCloud (`sync_from_nextcloud`):**
- Скачивает новые/измененные файлы из NextCloud
- **Удаляет локальные файлы, которых нет в NextCloud** (если `delete_missing=True`)
- Обновляет только файлы, которые новее в NextCloud (по дате модификации)

**Важно:** Удаление файлов включено по умолчанию (`SYNC_DELETE_MISSING=true`). Это обеспечивает полную синхронизацию между локальной копией и NextCloud.

**Отключение удаления файлов:**
Если вы хотите отключить автоматическое удаление файлов (например, для безопасности), установите:
```bash
SYNC_DELETE_MISSING=false
```

В этом случае файлы будут только добавляться и обновляться, но не удаляться при синхронизации.

### Исключение системных файлов

По умолчанию из синхронизации исключаются:
- **Dot-файлы/директории** (`.git/`, `.cursor/`, `.env`, `.DS_Store` и т.д.)
- **Кеш и зависимости** (`__pycache__/`, `node_modules/`)
- **IDE-конфиги** (`.idea/`, `.vscode/`)
- **Виртуальные окружения** (`.venv/`, `venv/`)

Если в базе знаний хранятся репозитории с кодом, их `.git/` директории, `node_modules/` и подобные файлы **не будут** скачиваться и загружаться.

Можно настроить собственные паттерны через переменную окружения:
```bash
SYNC_EXCLUDE_PATTERNS=.git/,__pycache__/,node_modules/,.DS_Store,.env,.venv/,venv/,.idea/,.vscode/,*.pyc
```

## Настройка

### Переменные окружения

```bash
# Включить синхронизацию
ENABLE_SYNC=true

# Автоматическая периодическая синхронизация
AUTO_SYNC=true
SYNC_INTERVAL=300  # секунд (5 минут)
SYNC_DELETE_MISSING=true  # Удалять файлы при синхронизации (true по умолчанию)

# Паттерны исключений (через запятую) — файлы/директории, которые НЕ синхронизируются
# SYNC_EXCLUDE_PATTERNS=.git/,__pycache__/,node_modules/,.DS_Store,.env,.venv/,venv/,.idea/,.vscode/

# NextCloud настройки
NEXTCLOUD_URL=https://your-nextcloud.com
NEXTCLOUD_BOT_USERNAME=telegram_knowledge_bot
NEXTCLOUD_BOT_PASSWORD=your_app_password
NEXTCLOUD_KNOWLEDGE_BASE_PATH=/KnowledgeBase

# Локальная папка
LOCAL_KB_PATH=/var/knowledge-base-bot/kb
```

### Для локальной разработки

```bash
# Отключить автоматическую синхронизацию (используется NextCloud клиент)
ENABLE_SYNC=false
AUTO_SYNC=false

# Или включить для тестирования
ENABLE_SYNC=true
AUTO_SYNC=true
SYNC_INTERVAL=60  # 1 минута для быстрого тестирования
```

### Для продакшена

```bash
# Включить автоматическую синхронизацию
ENABLE_SYNC=true
AUTO_SYNC=true
SYNC_INTERVAL=300  # 5 минут
```

## Использование

### Первый запуск

1. Убедитесь, что папка `LOCAL_KB_PATH` пуста или не существует
2. Запустите бота
3. Бот автоматически скачает базу знаний из NextCloud

### Работа с ботом

1. Отправьте текстовое сообщение боту
2. Бот обработает запрос через Cursor CLI
3. Если были изменения файлов, они автоматически синхронизируются с NextCloud
4. Вы получите уведомление о статусе синхронизации

### Принудительная синхронизация

Используйте команду `/sync` для принудительной синхронизации:
- Синхронизирует изменения в NextCloud (загружает локальные изменения)
- Синхронизирует изменения из NextCloud (скачивает удаленные изменения)
- **Автоматически удаляет файлы**, которые были удалены в одной из сторон

**Как работает удаление:**
- Если файл удален в NextCloud → он будет удален локально при синхронизации из NextCloud
- Если файл удален локально → он будет удален в NextCloud при синхронизации в NextCloud
- Это обеспечивает полную синхронизацию между двумя сторонами

## Структура синхронизации

```
NextCloud (сервер)
    └── KnowledgeBase/          # Расшаренная папка
        ├── Документация/
        ├── Templates/
        └── ...

        ⬇️ Синхронизация ⬆️

Локальная копия (Docker)
    └── /var/knowledge-base-bot/kb/
        ├── Документация/
        ├── Templates/
        └── ...
```

## Устранение проблем

### Бот не синхронизирует при первом запуске

**Проблема:** Локальная папка не пуста, но файлы не синхронизируются

**Решение:**
1. Проверьте логи бота
2. Убедитесь, что `ENABLE_SYNC=true`
3. Проверьте настройки NextCloud в `.env`
4. Используйте команду `/sync` для принудительной синхронизации

### Ошибки синхронизации

**Проблема:** Ошибки при синхронизации с NextCloud

**Решение:**
1. Проверьте логи бота на ошибки
2. Убедитесь, что NextCloud доступен
3. Проверьте правильность App Password
4. Проверьте права доступа пользователя бота к папке

**Ошибка 404 (Not Found):**
- Если файл был удален в NextCloud, но бот пытается его синхронизировать, это нормально
- Бот автоматически обрабатывает такие ошибки и пропускает удаленные файлы
- При следующей синхронизации файл будет удален локально (если включено `delete_missing=True`)

### Конфликты синхронизации

**Проблема:** Файлы изменены и локально, и в NextCloud

**Решение:**
- Текущая версия не разрешает конфликты автоматически
- Рекомендуется использовать периодическую синхронизацию для минимизации конфликтов
- При конфликтах приоритет отдается локальной версии (при загрузке в NextCloud)

## Рекомендации

### Для локальной разработки

- Используйте `ENABLE_SYNC=false` и синхронизируйте вручную через NextCloud клиент
- Или используйте `ENABLE_SYNC=true` с коротким интервалом для тестирования

### Для продакшена

- Включите `ENABLE_SYNC=true` и `AUTO_SYNC=true`
- Установите разумный интервал синхронизации (300-600 секунд)
- Мониторьте логи на ошибки синхронизации
- Регулярно проверяйте статус синхронизации через `/sync`
