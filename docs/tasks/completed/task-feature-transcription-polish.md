# Задача: Постобработка транскрипции голосовых сообщений через LLM

**Статус**: ✅ Выполнено  
**Приоритет**: 🟡 Средний  
**Категория**: Улучшения UX

## Описание

Расшифровка голосовых сообщений через Whisper работает корректно — текст распознаётся правильно. Однако качество оформления текста заметно уступает тому, что делает приложение ChatGPT при голосовом вводе: там текст выходит с правильной пунктуацией, заглавными буквами, без оговорок и слов-паразитов.

Гипотеза: помимо Whisper, ChatGPT пропускает транскрипцию через языковую модель для «полировки» — расстановки пунктуации, исправления капитализации, удаления оговорок и дублей.

Нужно реализовать аналогичную постобработку в боте.

## Проблема

Текущий результат Whisper (пример):
```
ну я сегодня ходил в магазин купил там значит молоко хлеб и ещё что-то ну там масло по-моему да масло и ещё сыр
```

Желаемый результат после постобработки:
```
Я сегодня ходил в магазин, купил молоко, хлеб, масло и сыр.
```

Типичные проблемы Whisper без постобработки:
- Отсутствие или неполная пунктуация (запятые, точки, вопросительные/восклицательные знаки)
- Неправильная капитализация (строчные буквы в начале предложений, имена собственные)
- Слова-паразиты и оговорки («ну», «значит», «как бы», «типа», «э-э», «ну там»)
- Повторы и самоисправления («масло по-моему да масло»)
- Отсутствие разбиения на абзацы в длинных текстах

## Решение

Добавить этап постобработки: после Whisper прогонять текст через LLM с промптом на «полировку». Вызов LLM — через Cursor CLI (`cursor-agent`), а не напрямую через OpenAI API.

### Почему Cursor CLI, а не OpenAI API напрямую

1. **В рамках подписки**: Cursor CLI работает через подписку Cursor, модели типа `gpt-4o-mini` и другие уже доступны — **нет дополнительных расходов** на API-токены OpenAI
2. **Единообразие**: весь бот работает через Cursor CLI, нет смысла вводить второй канал обращения к моделям
3. **Гибкость модели**: через `--model` можно легко переключать модель (gpt-4o-mini, claude-sonnet, и т.д.) без изменения кода
4. **Нет нужды в OPENAI_API_KEY**: у некоторых пользователей может быть только CURSOR_API_KEY, без отдельного ключа OpenAI

### Ключевое решение: когда полировать

Постобработка применяется **только при нажатии кнопки «🎤 Только транскрибировать»** — когда пользователь хочет получить красивый чистый текст.

Для остальных действий (запрос к БЗ, использование как prompt) полировка **не нужна** — LLM и так справится с «грязным» текстом, а лишняя обработка добавит задержку и потенциально может изменить смысл запроса.

**Также** полировать текст, который отправляется пользователю для предпросмотра сразу после транскрибации (в обычном режиме и в режиме сбора сообщений), **не нужно** — это добавит задержку. Предпросмотр показывается «как есть», а красивая версия доступна по кнопке.

## Задачи

### 1. Добавить легковесный метод `run_simple_prompt()` в CursorCLIService

Текущий `process_query()` слишком тяжёлый для полировки: он отслеживает изменения файлов (`_save_file_states` / `_get_file_changes`), строит контекст сессии, поддерживает стриминг и `--resume`. Для полировки нужен простой вызов «промпт → ответ».

- [x] Добавить метод `run_simple_prompt()` в `CursorCLIService`:
  ```python
  async def run_simple_prompt(
      self,
      prompt: str,
      model: Optional[str] = None,
      timeout: int = 30
  ) -> str:
      """
      Выполнить простой промпт через Cursor CLI без отслеживания файлов,
      без контекста сессии и без стриминга.
      
      Используется для вспомогательных задач (полировка текста и т.п.).
      
      Args:
          prompt: Текст промпта
          model: Модель (по умолчанию из TRANSCRIPTION_POLISH_MODEL)
          timeout: Таймаут в секундах
      
      Returns:
          str: Ответ модели (пустая строка при ошибке)
      """
  ```
- [x] Реализация:
  - Команда: `cursor-agent -p --model {model} "{prompt}"`
  - **Без** `_save_file_states` / `_get_file_changes` (нет отслеживания файлов)
  - **Без** `--resume`, `session_messages`, `attached_files`
  - **Без** `on_chunk` (не нужен стриминг)
  - Простой таймаут (30с по умолчанию, полировка — быстрая задача)
  - Возврат: текст ответа или пустая строка при ошибке
  - Обработка ошибок: логирование, но без прерывания (при ошибке возвращаем пустую строку)

## Архитектура

```
Голосовое сообщение
    ↓
download_telegram_file() → audio_path
    ↓
TranscriptionService.transcribe() → { text, language }   ← Whisper (OpenAI API)
    ↓
Показать предпросмотр "как есть"
    ↓
Пользователь нажимает кнопку:
    ├── "📤 Отправить как запрос"     → text → QueryProcessingService (без полировки)
    ├── "📝 Использовать как prompt"  → text → QueryBuilder (без полировки)
    └── "🎤 Только транскрибировать"  → CursorCLIService.run_simple_prompt() → ✨ красивый текст
                                              ↑
                                        cursor-agent -p --model gpt-4o-mini "{polish_prompt}"
                                        (в рамках подписки Cursor, без доп. расходов)
```

### Сравнение: Cursor CLI vs OpenAI API напрямую

| Аспект | Cursor CLI | OpenAI API напрямую |
|--------|-----------|---------------------|
| **Стоимость** | В рамках подписки Cursor (бесплатно) | ~$0.15/1M input + $0.60/1M output |
| **Зависимости** | `cursor-agent` (уже есть) | `openai` SDK (уже есть для Whisper) |
| **API ключ** | `CURSOR_API_KEY` (уже есть) | `OPENAI_API_KEY` (может не быть) |
| **Латентность** | ~2-5с (запуск subprocess + ответ) | ~1-3с (прямой HTTP-запрос) |
| **Выбор модели** | `--model` флаг, любые модели из подписки | Только модели OpenAI |
| **Единообразие** | Совпадает с остальной архитектурой бота | Второй канал вызова LLM |

**Вывод**: Cursor CLI предпочтительнее — нулевая стоимость, единообразие, гибкость. Небольшая доп. латентность (~1-2с) некритична для кнопки «Только транскрибировать».

## Детали реализации

### `CursorCLIService.run_simple_prompt()` — ключевые отличия от `process_query()`

| Аспект | `process_query()` | `run_simple_prompt()` |
|--------|-------------------|----------------------|
| Отслеживание файлов | ✅ `_save_file_states` + `_get_file_changes` | ❌ Не нужно |
| Контекст сессии | ✅ `session_messages`, `--resume` | ❌ Не нужно |
| Стриминг | ✅ `on_chunk` callback | ❌ Не нужно |
| Прикрепленные файлы | ✅ `attached_files` | ❌ Не нужно |
| Системный промпт | ✅ `.cursor/rules/` | ❌ Не нужно (промпт полировки самодостаточный) |
| Таймаут | 600с (10 мин) | 30с (полировка — быстрая задача) |
| Возвращаемое значение | `tuple[str, List[Dict]]` | `str` (только текст) |

### Подавление системного промпта

Важный момент: при вызове `cursor-agent` в директории БЗ Cursor CLI подхватывает `.cursor/rules/` (системный промпт бота). Для полировки он не нужен и может мешать.

Варианты решения:
1. **Запуск из другой директории** (например, `/tmp`) — тогда `.cursor/rules/` не подхватится
2. **Явное указание в промпте** — «Верни ТОЛЬКО исправленный текст» (текущий подход)
3. **`--no-context` флаг** — если поддерживается `cursor-agent` (проверить)

Рекомендуется вариант 1 (запуск из `/tmp` или другой нейтральной директории), чтобы системный промпт БЗ точно не влиял на результат полировки.

## Оценка

- **Сложность**: 🟢 Низкая
- **Время**: ~2-3 часа
- Основная работа — `run_simple_prompt()` в `CursorCLIService` и интеграция в callback

## Стоимость

- При использовании Cursor CLI: **$0** (в рамках подписки)
- Модели вроде `gpt-4o-mini` доступны в подписке Cursor без дополнительной оплаты
- Нет нужды в отдельном `OPENAI_API_KEY` для полировки

## Риски и митигация

| Риск | Вероятность | Митигация |
|------|------------|-----------|
| LLM искажает смысл (удаляет важные слова) | Средняя | Строгий промпт «НЕ меняй смысл»; тестирование на разных примерах |
| LLM добавляет отсебятину | Низкая | Промпт «верни ТОЛЬКО исправленный текст»; лёгкая модель (gpt-4o-mini) |
| Задержка на запуск subprocess + ответ (~2-5с) | Высокая | Применяется только для «Только транскрибировать»; показать «✨ Оформляю текст...» |
| Cursor CLI подхватывает системный промпт БЗ | Средняя | Запуск из нейтральной директории (`/tmp`), не из `kb_path` |
| Cursor CLI / подписка недоступна | Низкая | Fallback на оригинальный текст с предупреждением |
| Неправильная работа с техническими терминами | Средняя | Промпт «НЕ перефразируй»; тестирование |
| `gpt-4o-mini` недоступна в подписке пользователя | Низкая | Конфигурируемая модель через `TRANSCRIPTION_POLISH_MODEL`; fallback на модель из `CURSOR_MODEL` |
