# Задача: Кликабельные ссылки на файлы в ответах AI

**Статус**: 📋 Запланировано  
**Приоритет**: 🟡 Средний  
**Категория**: Улучшения UX

## Описание

Когда AI упоминает файлы базы знаний в ответе (например, «Нашёл файл `Документы/Тачки/Заправки/TEBOIL.md`»), путь отображается как текст без возможности перейти к файлу. Нужно превращать упоминания файлов в кликабельные ссылки на NextCloud.

## Проблема

Сейчас ссылки генерируются **только в уведомлении об изменениях** (когда AI создал или отредактировал файл). Но в самом тексте ответа пути остаются просто текстом:

```
Нашёл файл Документы/Тачки/Заправки/AЗС/TEBOIL М-2 Всходы.md    ← просто текст, не кликабельно
```

Типичные кейсы, где нужны ссылки:
- Пользователь просит найти файл → AI нашёл и упоминает путь
- AI цитирует информацию из файла и указывает источник
- AI перечисляет список подходящих файлов

## Решение: Гибридный подход (Cursor AI + пост-обработка)

Комбинация двух стратегий для максимальной надёжности:

### Этап 1: Маркеры в системном промпте

Добавить в системный промпт бота (`agent/system_prompt.md`) инструкцию для AI:

```markdown
## Формат ссылок на файлы

Когда ты упоминаешь файлы базы знаний в ответе, оборачивай полный путь в специальный маркер:
- Формат: `[[file:путь/к/файлу.md]]`
- Пример: `[[file:Документы/Тачки/Заправки/AЗС/TEBOIL М-2 Всходы.md]]`
- Используй этот формат ВСЕГДА, когда упоминаешь конкретный файл из базы знаний
- Путь должен быть относительным (от корня базы знаний)
- Маркер будет автоматически заменён на кликабельную ссылку для пользователя
```

**Важно:** Промпт должен быть написан так, чтобы AI понимал зачем это нужно и следовал инструкции стабильно. Нужно продумать формулировку — слишком жёсткая инструкция может ломать естественность ответов, слишком мягкая — будет игнорироваться.

### Этап 2: Пост-обработка ответа (замена маркеров + поиск путей)

После получения ответа от Cursor CLI, перед отправкой в Telegram:

1. **Замена маркеров** `[[file:...]]` → HTML-ссылка `<a href="...">`
2. **Регулярки (fallback)**: найти паттерны, похожие на пути к файлам (с расширениями `.md`, `.txt`, `.csv` и т.д.), которые не были обёрнуты в маркер
3. **Проверка существования**: для каждого найденного пути — проверить, существует ли файл локально (`Path.exists()`)
4. **Генерация ссылки**: если файл существует — получить ссылку через `NextCloudService.get_file_link()`
5. **Замена в тексте**: заменить путь на `<a href="url">📎 имя_файла</a>` (или `<code>путь</code>` если ссылка недоступна)

## Задачи

- [ ] Добавить секцию «Формат ссылок на файлы» в `agent/system_prompt.md`
- [ ] Продумать формулировку: достаточно строгая для стабильного соблюдения, но не ломающая естественность ответов
- [ ] Объяснить AI, зачем нужны маркеры (для мотивации следовать инструкции)
- [ ] Указать примеры правильного и неправильного использования

### 2. Создать модуль обогащения ссылками

- [ ] Создать `utils/link_enrichment.py` с функцией:
  ```python
  async def enrich_response_with_links(
      text: str,
      kb_path: Path,
      nextcloud_service: Optional[NextCloudService] = None,
  ) -> str:
      """
      Обогатить текст ответа кликабельными ссылками на файлы.
      
      1. Заменить маркеры [[file:path]] на HTML-ссылки
      2. Найти незамаркированные пути (fallback)
      3. Проверить существование файлов
      4. Сгенерировать ссылки через NextCloudService
      """
  ```

### 3. Парсинг маркеров `[[file:...]]`

- [ ] Регулярка для маркеров: `\[\[file:(.+?)\]\]`
- [ ] Извлечь путь, проверить существование, заменить на ссылку
- [ ] Если файл не найден — оставить просто `<code>путь</code>` (без ссылки, но и без маркера)

### 4. Fallback: поиск путей регулярками

- [ ] Регулярка для путей с расширениями: паттерны вида `слово/слово/файл.md`
- [ ] Поддерживаемые расширения: `.md`, `.txt`, `.csv`, `.json`, `.yaml`, `.yml`
- [ ] Исключить пути внутри блоков кода (```, <pre>) — чтобы не ломать код
- [ ] Исключить URL-подобные строки (http://, https://)
- [ ] Проверить существование файла локально (`kb_path / path`).exists()`)
- [ ] Если файл существует — заменить на ссылку (аналогично маркерам)

### 5. Интеграция в pipeline отправки

- [ ] Вызвать `enrich_response_with_links()` в `StreamingMessageUpdater.finalize()`:
  - После получения полного текста, перед конвертацией в HTML
  - Маркеры и пути заменяются на HTML-ссылки
  - Затем `markdown_to_html()` (или plain text fallback)
- [ ] Вызвать `enrich_response_with_links()` в `send_formatted_message()`:
  - Перед конвертацией `markdown_to_html()`
- [ ] Передать `kb_path` и `NextCloudService` в updater/helper

### 6. Кэширование ссылок

- [ ] Кэшировать результаты `get_file_link()` в рамках одного ответа (один файл может упоминаться несколько раз)
- [ ] Опционально: LRU-кэш для `get_file_link()` с TTL (share-ссылки живут 24ч, можно кэшировать на час)

## Вопросы для проработки

### Формулировка системного промпта

- Как сбалансировать строгость инструкции и естественность ответов?
- Нужно ли AI указывать, когда НЕ использовать маркер (например, при упоминании файла в общем контексте без конкретного пути)?
- Как обрабатывать ситуацию, когда AI упоминает папку (не файл)?

### Регулярки для fallback

- Какие расширения файлов поддерживать?
- Как отличить путь `Расходы/Топливо` от обычного текста с «/»?
- Нужен ли whitelist директорий верхнего уровня для повышения точности?

### Интеграция со стримингом

- При стриминге текст приходит чанками — маркеры могут быть разбиты между чанками
- Обогащение ссылками имеет смысл только при `finalize()`, не при промежуточных обновлениях
- Нужно ли показывать маркеры `[[file:...]]` пользователю во время стриминга, или заменять на путь без ссылки?

## Пример результата

**Было (текущее поведение):**
```
Нашёл файл Документы/Тачки/Заправки/AЗС/TEBOIL М-2 Всходы.md

В нём указано:
- Адрес: М-2 Всходы
- Бренд: TEBOIL
```

**Станет (с маркерами от AI + пост-обработка):**
```
Нашёл файл TEBOIL М-2 Всходы.md 📎 Открыть     ← кликабельная ссылка

В нём указано:
- Адрес: М-2 Всходы
- Бренд: TEBOIL
```

**Если AI забыл маркер (fallback):**
```
Информация в файле Документы/Тачки/Заправки/AЗС/TEBOIL М-2 Всходы.md 📎     ← найден по регулярке
```

## Оценка

- **Сложность**: 🟡 Средняя
- **Время**: ~4-6 часов
- Основная сложность — в надёжности парсинга путей и формулировке промпта

## Риски и митигация

| Риск | Вероятность | Митигация |
|------|------------|-----------|
| AI не следует инструкции про маркеры | Средняя | Fallback на регулярки; итерация формулировки промпта |
| Ложные срабатывания регулярок (текст распознан как путь) | Средняя | Проверка `Path.exists()`; whitelist расширений |
| Маркер `[[file:...]]` разбит между чанками стриминга | Низкая | Обогащение только в `finalize()` |
| Доп. запросы к NextCloud замедляют ответ | Средняя | Параллельные запросы; кэширование; локальная проверка `exists()` до запроса к NC |
| HTML-ссылки ломают форматирование Markdown | Средняя | Обогащение ДО `markdown_to_html()`; тесты |
