# Миграция на бинарник `agent` (Cursor CLI)

**Статус**: 📋 Запланировано  
**Приоритет**: 🟡 Средний  
**Категория**: Технические улучшения

## Описание

В актуальной документации и установщике Cursor CLI команда называется **`agent`** (проверка: `agent --version`, обновление: `agent update`, подкоманды: `agent create-chat`, `agent ls` и т.д.). В коде и документации бота по историческим причинам везде зашито **`cursor-agent`**.

На сервере со **старой** установкой CLI в `PATH` может быть только `cursor-agent`; после обновления до свежей версии — обычно **`agent`** в `~/.local/bin`. Поведение и флаги (`-p` / `--print`, `--force`, `--resume` и др.) в справке Cursor сохраняются; меняется **имя исполняемого файла**.

Нужно убрать расхождение: конфигурируемое имя бинарника, обновление сервера/образа и актуализация внутренней документации.

## Цели

1. Сделать имя CLI **настраиваемым** (переменная окружения, разумный дефолт для новых установок).
2. При необходимости сохранить **переходный период** (fallback или явная документация для symlink).
3. Обновить **деплой и проверки** (`which`, Docker, инструкции админу).
4. Привести в соответствие **документацию в репозитории** (где ещё фигурирует только `cursor-agent`).

- [ ] Заменить жёсткие строки `"cursor-agent"` в `CursorCLIService` на использование конфига; обновить тексты ошибок и комментарии.
- [ ] Проверить вызовы в `transcription_service.py` и других местах, если там дублируется имя бинарника.
- [ ] Обновить `DEPLOYMENT_SERVER.md` и связанные чеклисты: проверка `which agent`, установка PATH (`~/.local/bin`), при миграции со старого сервера — `agent update` или переустановка через официальный install.
- [ ] Обновить Docker/CI-фрагменты, если образ ставит CLI и проверяет бинарник по имени.
- [ ] Пройтись по `docs/` и при необходимости заменить устаревшие примеры на `agent` с пометкой о старом имени там, где это важно для истории.
- [ ] После выката на сервер: убедиться, что сессии (`create-chat`, `--resume`) и отмена процессов работают с новым именем.

### Риски

- На старом окружении без обновления CLI после смены дефолта на `agent` возможен `FileNotFoundError`, пока не задан `CURSOR_CLI_BIN=cursor-agent` или не обновлён CLI.
- Стоит явно описать в `DEPLOYMENT_SERVER.md` порядок: сначала обновить CLI / задать env, потом выкатывать версию бота с новым дефолтом (если дефолт будет `agent`).
