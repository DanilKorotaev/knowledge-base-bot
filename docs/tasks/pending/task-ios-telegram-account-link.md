# iOS: привязка Telegram в настройках

**Статус:** 📋 Planned

**Репозиторий:** `knowledge-base-app-ios` (этот файл лежит в backend, iOS-репозиторий не менять из задачи бота)

## Зачем

Telegram-бот и Mini App работают только от аккаунта приложения. Код привязки выдаёт API. В iOS кнопки ещё нет: человек не может получить код из приложения.

## Что показать

Экран настроек аккаунта (рядом с профилем / Nextcloud):

- Если `user.telegram_linked == false`: кнопка «Привязать Telegram».
- Если `true`: «Привязан» и `user.telegram_username` (если есть), кнопка «Отвязать».

Поля уже есть в `GET /api/auth/me` → `user`:

| Поле | Смысл |
|------|--------|
| `telegram_linked` | bool |
| `telegram_id` | число или `null` |
| `telegram_username` | строка или `null` |

## Вызовы

1. `POST /api/auth/telegram/link` с текущим access token.  
   Ответ: `code`, `command` (например `/link ABCD2345`), `expires_at`, `purpose=link`.  
   Показать код и открыть `https://t.me/<бот>?start=link_КОД`. Код одноразовый, около 20 минут.
   Бот сам не привязывает по открытию ссылки: человек видит логин и жмёт «Да, привязать» или «Нет».
2. После того как человек отправил код боту, обновить экран через `GET /api/auth/me` (pull-to-refresh или кнопка «Проверить»). Отдельного webhook в приложение нет.
3. `DELETE /api/auth/telegram/link` — отвязать. Сессии в приложении остаются.

Ошибки API в теле `{ "error": { "code", "message" } }`. `409` — этот Telegram уже занят другим аккаунтом или у аккаунта уже другой Telegram.

## Чего не делать в iOS

- Не встраивать Bot API и не хранить токен бота.
- Не заводить отдельного пользователя Telegram. Сессии бота — те же `GET /api/sessions` этого аккаунта.
- Не закрывать сессию приложения, когда в Telegram нажали «новый чат»: бэкенд этого уже не делает.

## Готово, когда

- [ ] Непривязанный аккаунт получает код и видит команду для бота
- [ ] После `/link` в боте экран показывает `telegram_linked`
- [ ] Отвязка сбрасывает флаг
- [ ] Чужой или просроченный код показывает сообщение API, а не пустой экран
